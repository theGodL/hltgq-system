## 一、监控口径：只记人工操作

### 1.1 基本原则

只记录**人工操作**产生的数据增删改；由设备、模型服务、同步程序、定时任务自动写入的数据**一律不记录**。

判定方法（实测验证）：

| 写入来源 | 审计字段特征 | 实例 |
| --- | --- | --- |
| 机器/系统写入 | `created_by` / `updated_by` = `SYSTEM`（或系统账号） | 告警 `water_alert` 1773 条全部 SYSTEM；设备 `water_device` 的 404 条更新全部 SYSTEM |
| 人工操作 | 真实用户短 ID（形如 `VDLqdrLqoRQkmH7tltL`） | 工单 `water_work_order` 1745 条中 4 条为人工 |

**混合表处理**：同一张表既有机器生成又有人工操作时（如工单表），按操作人字段过滤，仅保留人工操作记录。

### 1.2 机器写入的典型场景（不记录）

1. 设备/报文监测数据入库（雨量、水位、流量、闸门、墒情、水质等，行数数万级）；
2. 模型计算的明细/汇总数据（随方案整体生成与删除）；
3. 告警自动生成与自动关闭（设备数据入库时触发）；
4. 设备台账同步（`water_device` 主要由同步程序维护）；
5. 视频巡查统计数据、系统资源采样、故障记录等内部日志；
6. 平台发布时生成的 `_bak_v*` 备份表。

### 1.3 操作类型与识别方法

| 操作 | 识别依据 | 备注 |
| --- | --- | --- |
| 新增 | `created_at` 水位线增量扫描 | 操作时间取 `created_at`、操作人取 `created_by` |
| 修改 | `updated_at` 增量 + 行级字段 diff | 操作时间取 `updated_at`、操作人取 `updated_by` |
| 删除 | "上次快照存在、本次消失"差集，或数据库侧捕获 | **物理删除必须删除前捕获**（见第五章）；**软删（假删除）按删除记录** |

`created_by` / `updated_by` 存的是用户中心 `t_apaas_uc_user.id` 短 ID，展示姓名需 JOIN 用户表解析（建议日志落库时冗余 `operator_name`）。

## 三、专项说明

### 3.1 视频监测 / 云台控制（无表，DB 侧无法监控）

- 已核实：hltgq-site 代码中**不存在任何云台/PTZ/预置位实现**；数据库中也无对应表。
- 视频相关数据仅有转发统计（`water_video_patrol` 约 26.5 万行，机器写入，不记录）。
- **答复**：是的——云台控制若不落库，数据库扫描无从监控；如确需审计控制行为，应在 **hltgq-device**（对接大华平台）侧对控制指令打点。**建议本次不纳入监控清单**，待 hltgq-device 侧方案明确后再补充。

### 3.2 站点排序表（多菜单共用一张表）

`t_auto_hltgq_water_station_sort`（152 行）同时服务："灌区综合管理系统>站点排序"与"运行监测>水位/雨量/流量/闸门/墒情监测>站点排序"。区分维度：`type`=waterLevel/rainfall/flow/gate/moisture，`scope`=reservoir/gq。仅系统管理员（@RequireAdmin）可操作。日志监控只需盯这一张表。

### 3.3 雨量数据维护（软删 + 补偿）

- 雨量监测数据由设备海量写入（42,443 行），**只记录人工干预**：数据维护页的删除（软删占位）与恢复，并联动补偿值表 `water_rain_adjust`；删除操作需填补偿值、仅管理员、三级护栏。

- 水位监测数据（`water_river_info` 42,586 行）**无页面维护入口**（遗留接口未被页面调用），暂不纳入；如后续开放需补充。

## 六、实现要点建议（供编码参考）

1. **操作人解析**：`created_by`/`updated_by` → JOIN `t_apaas_uc_user`；日志落库冗余 `operator_id`+`operator_name`，防止改名/离职后无法追溯。
2. **操作时间**：新增取 `created_at`；修改取 `updated_at`；删除以捕获时刻为准。
3. **增/改识别**：按 `updated_at` 水位线增量拉取 + 行级快照 diff（水位线带安全回退窗口）。
4. **删除识别**：快照差集/"上次存在本次消失"；`deleted`/标记字段翻转（如 `water_rain_info.deleted`）归类为删除。
5. **人工过滤**：扫描时排除 `created_by`/`updated_by` = `SYSTEM` 的记录（告警、设备同步、模型回写均命中此规则）。
6. **高频降噪**：`water_message_receive`（已读状态）等交互表按时间窗口合并，仅保留最终状态。
7. **敏感字段**：用户 `pwd` 变更只记"重置密码"事件；组织管理密码规则字段记字段级变更（值本身非敏感，可记）。
8. **建议日志表结构**：

| 字段 | 说明 |
| --- | --- |
| log_id | 主键 |
| table_name / form_name | 物理表名 / 表单中文名 |
| biz_id | 业务记录 ID |
| op_type | INSERT / UPDATE / DELETE |
| op_at | 操作时间（取自表内审计字段） |
| operator_id / operator_name | 操作人 |
| before_json / after_json | 变更前后快照（删除时仅 before） |
| created_at | 日志记录时间 |
