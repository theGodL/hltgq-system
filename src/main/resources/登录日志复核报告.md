> 复核时间：2026-10-13
> 复核方式：只读 SQL（系统目录扫描 + 精确 COUNT(*) 计数），未做任何写操作

用户预期"这个库里应该有对应的（登录日志）表单"。复核结果分两层：

## 二、复核发现

### 2.1 平台内建"日志中心"表族存在，结构上支持登录日志

平台自带的日志中心表族共 10 张表，其中主表 `t_apaas_loghub_data` 共 35 列，**登录日志与操作日志共用一张表**，字段按用途可分三类：

**登录日志相关字段**：

| 字段 | 含义 |
| --- | --- |
| `login_by` | 登录人（用户 ID） |
| `login_at` | 登录时间 |
| `logout_at` | 登出时间 |
| `ip` | 登录 IP |
| `terminal` | 终端信息 |
| `action` | 动作 |
| `type` | 类型（区分登录日志 / 操作日志） |
| `content` | 内容摘要 |

**操作日志相关字段**（供另一项需求参考）：

| 字段 | 含义 |
| --- | --- |
| `operator` | 操作人 |
| `app_id` / `model_id` | 应用 / 模型标识 |
| `biz_id` / `biz_title` | 业务记录 ID / 标题 |
| `value_logs` | 字段值变更日志（快照） |
| `opt_event` / `opt_time` | 操作事件 / 操作时间 |
| `trigger_id` / `trigger_start` / `trigger_end` / `duration` | 触发链路与耗时 |
| `status` | 执行状态 |
| `headers` / `body` | 请求报文 |

**通用字段**：`id`、`corp_code`（租户）、`created_at` / `created_by` / `updated_at` / `updated_by`（审计列）。

配套表：`t_apaas_loghub_data_001`（分表）、`t_apaas_loghub_data_temp`、`t_apaas_loghub_data_level`（明细）、`t_apaas_loghub_rule`（记录规则）、`t_apaas_loghub_rule_temp`、`t_apaas_loghub_setting`（全局设置）、`t_apaas_loghub_setting_temp`、`t_apaas_loghub_app_rule`、`t_apaas_loghub_app_rule_temp`。

### 2.2 数据实测：日志中心从未产生任何记录（精确计数）

2026-10-13 对全部 loghub 表逐张执行 `COUNT(*)` 精确计数，结果如下：

| 表名 | 精确行数 | 说明 |
| --- | --- | --- |
| `t_apaas_loghub_data` | **0** | 日志主表（登录 + 操作），全库零记录 |
| `t_apaas_loghub_data_001` | **0** | 日志分表 |
| `t_apaas_loghub_data_temp` | **0** | 临时表 |
| `t_apaas_loghub_data_level` | **0** | 明细表 |
| `t_apaas_loghub_setting` | **0** | 日志设置，从未配置 |
| `t_apaas_loghub_rule` | 110 | 记录规则 110 条，归属见 2.3 |
| `t_apaas_loghub_rule_temp` | 110 | 规则临时表（同内容） |
| `t_apaas_loghub_app_rule` | 7 | 应用级规则 |
| `t_apaas_loghub_app_rule_temp` | 7 | 应用级规则临时表 |

**关键事实：主数据表 0 行，说明该日志中心自部署以来从未写入过任何一条日志（无论登录日志还是操作日志）。**

### 2.3 规则归属分析：hltgq 租户 0 条

对 `t_apaas_loghub_rule` 的 110 条规则按租户聚合：

- 涉及租户：`1125qatest`、`1125test`、`companytest_002`、`default`、`gh`、`gh02`、`guanqu`、`junjun`、`lijun`、`p001`、`p0011`、`qatest01`、`qatest02`、`qgu`、`qgutech`、`qxtest`、`test001`、`test003`、`test006`~`test014`、`th001`~`th008`、`wanglt`、`wlt001`~`wlt006`、`zff` 系列、`zhang` 系列等（均为平台方测试/演示租户）；
- 规则指向的应用全部是平台内建应用（`H0DL8gQ40M9tOje8Cgw`、`Z9XGpyCkeItyhpUG4US` 等，属平台自带管理应用）；
- **`SELECT count(*) FROM t_apaas_loghub_rule WHERE corp_code = 'hltgq'` → 0 条**。

即：hltgq 租户从未在平台日志中心配置过任何"要记录哪些表"的规则，平台不会为 hltgq 生成任何日志（这也解释了为何 data 表全库为空）。

### 2.4 "登录信息"（loginInfo）模型复核：内存模型，无物理表

- 平台 default 租户存在名为"登录信息"的模型 `loginInfo`（应用 `MRZtdB0Z7E1nh8YfXdm`，状态 #PUBLISHED#）；
- 该模型类型为 **`#MEMORY#`（内存模型）**，在模型-物理表映射表 `t_lcode_model_table` 中无对应行；
- 因此该"登录信息"不是持久化的登录日志表单——不落库、不可查询，无法作为登录日志数据源。

### 2.5 用户中心无登录审计字段

- `t_apaas_uc_user`（hltgq 租户现有 150 名用户）中与登录相关的字段**仅有 `login_name`**，没有"最后登录时间 / 最后登录 IP / 登录次数"等审计字段；
- 全库表名扫描未发现 sign / visit / session 类的登录审计表（命中的少量 visitor 表均为其他租户的访客业务表，与登录无关）。

### 2.6 旁证：业务活跃，但登录零记录

- hltgq 租户现有 150 名用户；业务数据自 2026-05 起持续写入，且 2026-09 有明显真实使用（实测抽样：应急事件表 2026-09-08 ~ 09-14 连续多次操作；公众服务数据 2026-09-03 ~ 09-18 录入更新；值班交接班 2026-10-12 完整闭环录入）；
- 与此同时 `t_apaas_loghub_data` 全库 0 行；
- 结论：不是"环境没人用过"，而是**登录日志/日志中心的记录能力在该环境下从未启用**。

## 三、复核结论

| # | 检查项 | 复核结论 |
| --- | --- | --- |
| 1 | 登录日志表是否存在 | 平台日志中心表存在且字段完备（`login_by` / `login_at` / `logout_at` / `ip` / `terminal`），但属平台级共享结构，并非 hltgq 业务表单 |
| 2 | 表是否正常（有数据） | **不正常**：0 条数据，从未写入 |
| 3 | hltgq 是否配置记录规则 | **否**：0 条规则 |
| 4 | "登录信息"（loginInfo）模型 | 存在但为内存模型（#MEMORY#），无物理表 |
| 5 | 用户表登录审计字段 | 无（仅 login_name） |
| 6 | 能否查到登录记录 | **不能**：当前库中无任何可用登录日志数据 |

**综合结论**：库中不存在"正常工作的登录日志表单"。登录日志功能在 hltgq 环境下处于"表在、功能未启用、数据为空"的状态。此项需求无法通过当前数据库满足，**建议在新项目 hltgq-system 中自建登录日志功能**。

## 四、建议（供 hltgq-system 实施参考）

### 4.1 自建登录日志表（建议字段）

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `user_id` | 用户 ID（对应平台 `t_apaas_uc_user.id`） |
| `login_name` | 登录账号 |
| `user_name` | 用户姓名 |
| `org_name` | 所属机构（归档便于展示） |
| `login_at` | 登录时间 |
| `logout_at` | 登出时间（会话失效时回填） |
| `login_ip` | 登录 IP |
| `user_agent` | 浏览器/客户端 UA |
| `terminal` | 终端类型（PC / H5 / 三维系统） |
| `login_type` | 登录方式（账号密码 / 三维 SSO / 免登） |
| `status` | 登录结果（成功 / 失败） |
| `fail_reason` | 失败原因（可选） |
| `session_id` | 会话标识（可与登出配对） |
| `online_duration` | 在线时长（登出时计算） |
| `created_at` | 记录创建时间 |

### 4.2 记录时机建议

1. **登录成功**：写入一条（含 IP、UA、登录方式）；
2. **登录失败**：写入一条（含失败原因，便于安全审计）；
3. **登出 / 会话超时**：回填 `logout_at` 与在线时长；
4. （可选）会话续期时刷新活跃时间。

### 4.3 与现有登录体系的关系

- 当前 hltgq-site 的登录态来源于低代码平台会话（`SessionContextService` / `UserContextHolder`）及三维 SSO 代理；
- hltgq-system 若作为新的登录入口承接账号登录，可直接在鉴权环节落库登录日志；
- 若仍复用平台会话或第三方单点登录，需评估在会话校验链路上定位"登录事件点"（首个会话建立时刻）。

### 4.4 备选方案说明（不推荐作为主方案）

联系平台方为 hltgq 租户启用日志中心并配置记录规则（当前规则数 0）。但需注意：全库至今没有任何一条成功产生的日志数据，平台侧功能未经实际验证；且启用后能否覆盖登录事件也取决于平台实现。因此仅作为备选，不建议作为主方案。
